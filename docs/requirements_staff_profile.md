# 要件定義書
## 要員プロフィール管理機能（インポート・表示・編集・保存）

**文書バージョン**: 1.0
**作成日**: 2026-03-16
**対象システム**: 要員アサイン管理システム（TMS）

---

## 1. 目的・背景

当社（コンサルティング会社）における要員のアサインを効率的・効果的に行うため、要員の経験・スキルを一元管理するシステムを構築する。本フェーズでは、要員プロフィールのインポートから表示・修正保存までの機能を対象とする。

---

## 2. スコープ

本要件定義書が対象とする機能範囲は以下のとおり。

| No | 機能 | 説明 |
|----|------|------|
| 1 | プロフィールインポート | Word / PPT / PDF 形式の職務経歴書を読み込み、情報を抽出・登録する |
| 2 | プロフィール表示 | 登録済み要員のプロフィールを閲覧する |
| 3 | プロフィール編集・保存 | 登録情報を修正し、保存する |
| 4 | LLM解析 | フリーテキストを含む経験情報を解析し、経験タグ・人材説明文を自動生成する |

---

## 3. ユーザー・権限

### 3.1 ユーザーロール

| ロール | 説明 | 閲覧 | 編集 |
|--------|------|------|------|
| 本人 | 当該要員本人 | 自分のプロフィールのみ | 自分のプロフィールのみ |
| 上長 | 当該要員の直属上長および管理職 | 配下要員のプロフィール | 配下要員のプロフィール |
| 管理者 | システム管理者 | 全要員 | 全要員 |

### 3.2 アクセス制御方針

- ログイン認証必須。未認証状態でのアクセスは不可。
- 本人・上長・管理者以外は当該要員のプロフィールを閲覧できない。
- 権限外の操作を試みた場合はエラー画面（403）を表示する。

## 4. データ管理方針

### 4.1 管理対象情報

#### 4.1.1 基本情報

| フィールド | 格納内容 | 表示内容 | 備考 |
|------------|----------|----------|------|
| 氏名 | 氏名（漢字・カナ） | 表示する | |
| 年齢 | 生年月日（内部保持） | 年齢のみ表示 | 生年月日は画面に表示しない。年齢はシステム日付から動的に算出し常に最新値を表示する |
| 最寄り駅 | 最寄り駅名 | 表示する | 住所は管理しない |
| 所属部署 | 部署名 | 表示する | |
| 入社年月 | 入社年月 | 表示する | |

#### 4.1.2 除外する個人情報

以下の情報はシステムに登録・保持しない。

- 住所（都道府県・市区町村・番地・建物名）
- 生年月日の画面表示（内部計算用途にのみ使用し、表示・出力しない）
- 電話番号・メールアドレス（業務連絡は別途人事システムで管理）
- マイナンバー・社会保険番号

#### 4.1.3 資格・保有スキル

| フィールド | 内容 |
|------------|------|
| 資格名 | 取得資格の名称（例：PMP、情報処理技術者試験など） |
| 取得年月 | 資格取得年月 |
| 有効期限 | 有効期限がある場合のみ |

#### 4.1.4 プロジェクト経験

| フィールド | 内容 |
|------------|------|
| プロジェクト名 | 案件・プロジェクトの名称 |
| 期間（開始・終了） | 参画期間 |
| 役割・担当 | 担当したポジション・役割 |
| 業種 | クライアントの業種 |
| 概要・成果 | フリーテキストで記述可能 |

#### 4.1.5 ITスキル（重点管理）

IT関連スキルは他の経験と区別して重点管理する。

| フィールド | 内容 |
|------------|------|
| カテゴリ | 「開発言語」「フレームワーク」「インフラ」「ITソリューション/プロダクト」「データ/AI」「クラウド」「その他IT」のいずれか |
| スキル名 | 具体的な技術名（例：Python、AWS、Salesforce） |
| 習熟レベル | 初級 / 中級 / 上級 |
| 経験年数 | 年単位で記録（小数点第1位まで許容） |

### 4.2 センシティブ情報の取り扱い

- 生年月日は登録時に内部DBへ格納するが、APIレスポンス・画面表示・帳票出力のいずれにも含めない。
- 年齢はAPI呼び出し時にサーバー側で動的計算して返却する（フロントで計算しない）。
- DBの生年月日カラムは暗号化して保存する。

## 5. 機能要件

### 5.1 プロフィールインポート機能

#### 5.1.1 概要

Word（.docx）、PowerPoint（.pptx）、PDF の職務経歴書ファイルをアップロードし、テキストを抽出してプロフィール情報を取り込む。

#### 5.1.2 インポートフロー

```
[ファイルアップロード]
    ↓
[テキスト抽出] ← docx / pptx / pdf パーサー
    ↓
[LLM解析] ← 構造化情報の抽出（氏名、資格、経験、ITスキルなど）
    ↓
[プレビュー表示] ← ユーザーが抽出結果を確認・修正
    ↓
[確定保存]
```

#### 5.1.3 対応ファイル形式

| 形式 | 拡張子 | 最大ファイルサイズ |
|------|--------|------------------|
| Word | .docx | 20 MB |
| PowerPoint | .pptx | 20 MB |
| PDF | .pdf | 20 MB |

#### 5.1.4 テキスト抽出

- docx: python-docx 等のライブラリでテキスト・表・箇条書きを抽出する
- pptx: python-pptx 等でスライド本文・テキストボックスを抽出する
- pdf: pdfminer / pypdf 等でテキストレイヤーを抽出する（スキャンPDFは OCR 対象外とし、エラー通知する）

#### 5.1.5 LLMによる構造化抽出

抽出されたテキストをLLMへ入力し、以下の項目を構造化データとして出力させる。

- 氏名、最寄り駅、所属、資格、プロジェクト経験（期間・役割・業種・概要）
- ITスキル（カテゴリ別分類・経験年数の推定）
- フリーテキスト部分はそのまま保持

LLMへのプロンプトはシステム側で管理し、アプリケーション設定として変更可能にする。

#### 5.1.6 インポートプレビュー画面

- LLMが抽出した内容をフォーム形式で表示する。
- ユーザーはフォームを修正してから「確定」ボタンで保存できる。
- 「キャンセル」でインポートを中断し、ファイルを廃棄する。

#### 5.1.7 エラー処理

| エラー種別 | 対応 |
|------------|------|
| 非対応ファイル形式 | アップロード時にエラーメッセージ表示 |
| スキャンPDF（テキスト抽出不可） | エラーメッセージ表示、手動入力へ誘導 |
| ファイルサイズ超過 | アップロード時にエラーメッセージ表示 |
| LLM解析失敗 | エラーメッセージ表示、手動入力モードで継続可能 |

### 5.3 プロフィール編集・保存機能

#### 5.3.1 編集可能な項目

- 基本情報（氏名・最寄り駅・所属・入社年月）
- 資格（追加・修正・削除）
- プロジェクト経験（追加・修正・削除）
- ITスキル（追加・修正・削除）
- フリーテキスト部分

#### 5.3.2 編集不可項目

- 生年月日（変更は管理者権限のみ、別途管理メニューで対応）
- LLM生成の経験タグ・人材タイプ説明（再解析ボタンで更新）

#### 5.3.3 保存フロー

```
[編集画面で修正]
    ↓
[「保存」ボタン押下]
    ↓
[バリデーション]
    ↓ 成功
[DB更新]
    ↓
[LLM再解析トリガー（非同期）]
    ↓
[保存完了メッセージ表示]
    ↓
[経験タグ・説明文が更新されたら画面反映]
```

#### 5.3.4 バリデーション

| 項目 | ルール |
|------|--------|
| 氏名 | 必須・最大50文字 |
| 最寄り駅 | 任意・最大50文字 |
| 資格取得年月 | 形式: YYYY/MM |
| プロジェクト期間 | 開始年月 ≦ 終了年月（現在進行中は終了年月なし可） |
| ITスキル経験年数 | 0.5以上・50以下・0.5刻み |
| フリーテキスト | 最大5,000文字/項目 |

#### 5.3.5 楽観的ロック

- 複数ユーザーが同一プロフィールを同時編集した場合、後から保存しようとしたユーザーに競合エラーを通知し、再読み込みを促す。

### 5.4 LLM解析機能

#### 5.4.1 解析トリガー

| トリガー | タイミング |
|----------|------------|
| インポート時 | ファイルアップロード後のテキスト抽出後 |
| 保存時 | プロフィール情報が更新された後（非同期） |
| 手動再解析 | 「再解析」ボタン押下時 |

#### 5.4.2 出力内容

**① 経験タグ**

- 業種・職種・技術領域・役割などをキーワード化してタグとして出力する。
- 各タグに経験年数（年単位、小数第1位まで）を付与する。
- 経験年数はプロジェクト経験の期間情報とフリーテキストの記述から推定する。
- タグの最大数は50件とする。

**② 人材タイプ説明文**

- その人材が「どのような経験を持つ人物か」を3〜5文程度の自然言語で説明する。
- 検索・アサイン判断に使えるよう、得意領域・業種・役割を明示する。
- 最大200文字（日本語換算）とする。

#### 5.4.3 IT関連タグの重点管理

- ITスキルテーブルに登録されたスキルに対応するタグは「ITスキルタグ」として区別する。
- ITスキルタグは経験タグ一覧において上位・別色で表示する。
- 経験年数はITスキルテーブルの値を正として使用する（LLM推定値より優先）。

#### 5.4.4 非同期処理

- LLM解析はバックグラウンドジョブとして非同期実行する。
- 解析中はプロフィール画面上に「解析中...」インジケーターを表示する。
- 解析完了後、画面をリロードせずにタグ・説明文をリアルタイム更新する（WebSocket or ポーリング）。
- 解析に失敗した場合は旧タグ・旧説明文をそのまま保持し、エラーログを記録する。

## 6. 非機能要件

### 6.1 パフォーマンス

| 項目 | 目標値 |
|------|--------|
| プロフィール表示応答時間 | 1秒以内（P95） |
| ファイルアップロード+テキスト抽出 | 30秒以内 |
| LLM解析（非同期） | 60秒以内 |
| 保存処理応答時間 | 2秒以内（P95） |

### 6.2 セキュリティ

- 通信はすべてHTTPS（TLS 1.2以上）を使用する。
- 生年月日はDBで暗号化保存（AES-256）する。
- APIエンドポイントは認証トークン（JWT等）で保護する。
- アップロードファイルはウイルススキャンを実施する。
- ファイルはテキスト抽出後に削除し、長期保存しない。

### 6.3 可用性・信頼性

- LLMサービスが一時的に利用不可の場合でも、基本的なプロフィール登録・閲覧・編集は継続できる。
- LLM解析失敗時はリトライキューに入れ、最大3回リトライする。

### 6.4 ユーザビリティ

- モバイル対応（レスポンシブデザイン）。
- 日本語UIのみ（初期フェーズ）。

## 8. データモデル（概要）

```
members（要員）
  id, name, name_kana, department, join_ym,
  date_of_birth_enc (暗号化), nearest_station,
  profile_description (LLM生成説明文),
  created_at, updated_at, version

qualifications（資格）
  id, member_id, name, acquired_ym, expiry_ym

project_experiences（プロジェクト経験）
  id, member_id, project_name, start_ym, end_ym,
  role, industry, description (フリーテキスト)

it_skills（ITスキル）
  id, member_id, category, skill_name, level,
  years_of_experience

experience_tags（経験タグ）
  id, member_id, tag_name, years_of_experience,
  is_it_skill, source_skill_id (FK to it_skills, nullable),
  created_at
```

## 9. 外部インターフェース

| 種別 | 概要 |
|------|------|
| LLM API | プロフィール解析用。Anthropic Claude API（またはAzure OpenAI等）を使用。プロンプトはシステム設定で管理 |
| ファイルパーサー | python-docx / python-pptx / pdfminer（またはpypdf）|
| 認証基盤 | 既存の社内認証基盤（SAML/OIDC等）と連携、またはJWT認証を内製 |

## 10. 前提・制約・除外事項

| 種別 | 内容 |
|------|------|
| 前提 | インターネット接続が可能な環境でLLM APIを呼び出す |
| 前提 | アップロードされるPDFはテキストレイヤーを持つものとする（スキャンPDFは対象外） |
| 除外 | アサインマッチング機能（次フェーズ以降） |
| 除外 | 検索・絞り込み機能（次フェーズ以降） |
| 除外 | 帳票出力機能（次フェーズ以降） |
| 除外 | 組織・上長関係のマスタ管理 |

## 11. 用語定義

| 用語 | 定義 |
|------|------|
| 要員 | 当社のコンサルタント・エンジニアなど、アサイン対象の社員 |
| 経験タグ | LLMが業種・職種・技術領域・役割などを解析して生成するキーワードタグ。それぞれ経験年数を持つ |
| ITスキルタグ | 経験タグのうち、ITスキルテーブルと対応するもの。重点管理対象 |
| 人材タイプ説明文 | LLMがその要員の経験を要約して生成する自然言語の説明文 |
| 上長 | 当該要員の直属の上長および管理職 |
